## 1. 意图表

> 用户会问什么、归成哪几类。**这是最重要的一张表**——路由和评测都靠它。
> 颗粒度建议：一个意图大致对应一件能办成的事，别细到每个字段，也别粗到「问答」。

| 意图 ID | 意图名称 | 类型 | 用户可能的问法（多写几条） | 需要哪些工具 |
|---------|----------|------|---------------------------|--------------|
| renewal.status | 查询续期状态 | tool | 我的保单什么时候到期；续期成功了吗 | renewal.queryStatus |
| renewal.premium | 计算应缴保费 | tool | 这一期要交多少钱 | renewal.calcPremium |
| … | | tool/rag/chat/handoff | | |

**类型说明**：`tool`=要调工具　`rag`=查知识库/条款　`chat`=闲聊　`handoff`=直接转人工

---

## 2. 工具清单

> **一个工具 = 一个业务动作**。不要写「修改某个字段」这种，要写「办一件事」。
> 写操作尤其要把业务规则说清楚（比如犹豫期校验），规则会封在工具内部。

| 工具名 | 中文名 | 干什么 | 必填参数 | 可选参数 | 返回什么 |
|--------|--------|--------|----------|----------|----------|
| renewal.queryStatus | 查询续期状态 | 查保单的到期日、应缴状态、宽限期 | 保单号 | — | 到期日、状态 |
| | | | | | |

## 6. 兜底与转人工

| 项 | 内容 |
|----|------|
| 答不了转给谁 | 例：续期组一线客服 |
| 什么情况必须转人工 | 例：涉及金额争议、投诉倾向 |
| 转人工时对用户说什么 | 例：正在为您转接续期专员… |

---

## 7. 边界（告诉我你们「不管」什么）

> 这一栏能帮开发避免误判。写清楚哪些问题**不属于你们**。

- 例：涉及现金价值试算的，属保全，不属续期。
- 例：涉及欠费的，属财务，我们只提供续期状态。
