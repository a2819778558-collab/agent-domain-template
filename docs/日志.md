# 项目日志

这个骨架从设计到落地的过程记录。每一篇对外文章对应这里的一次更新。

## 2026-10-03 · 域插件契约定稿，路由器改造完成

**做完了**

- 域插件契约定稿：`DomainPlugin` / `ToolSpec` / `IntentSpec` / `PermissionPolicy` / `FallbackPolicy`
- 平台层：`DomainRegistry` 收集全部域，`DomainToolAssembler` 装配多域工具并集
- 路由输出从单个域改成**域集合**（`RouteResult.domains` 是 `Set`），跨域问题不再被砍能力
- `finance` 域写成完整样板，`renewal` / `servicing` / `protection` 留骨架
- 加 `docs/域接入登记表.md`——给业务专家填的表，不用懂代码

**踩的坑**

- 一开始把业务流程写进 system prompt，单域能用，跨域问句会漏答。加规则加到 prompt 变成规则手册，还是不好用。
- 根子上是把「域」当成了执行边界。改成「管理单位」之后就通了，代码改动其实只有一个 `Set`。

**跑起来的样子**

```
用户：我这保单下个月到期，想用现金价值续一下，顺便看看有没有欠费
路由：domains=[servicing, renewal, finance], confidence=1.00
装配工具(7)：跨域取数，三个域分别返回 现金价值 / 续期状态 / 欠费明细
```

`mvn compile exec:java` 可复现。

## 已知不足

- 路由器是 `KeywordRouter`，最简关键词实现，真实场景跑不了，仅用于演示「路由输出是域集合」
- 没有评测集，阈值只能拍脑袋
- `DomainToolAssembler` 是 O(n) 全量并集，工具多了会撑不住
